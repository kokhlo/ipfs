# Contributing to kokhlo/ipfs

Thanks for your interest in improving the only native IPFS client library in
the Ada/Alire ecosystem.

## Project layout

| Path | Contents |
|---|---|
| `src/` | Library units (`IPFS.Varint`, `IPFS.SHA256`, `IPFS.Multibase`, `IPFS.Multihash`, `IPFS.CID`, `IPFS.DagPB`, `IPFS.UnixFS`, `IPFS.CAR`, `IPFS.Gateway`) |
| `test/` | Test suites (one package per codec) + `ipfs_tests_runner` |
| `test/fixtures/` | Binary fixtures generated by kubo 0.43 (see `MANIFEST.txt`) |
| `examples/` | Runnable demos (`fetch_cid`, `fetch_car_demo`, `nebula_demo`) |
| `config/` | Alire-generated config project (do not edit by hand) |

## Prerequisites

- GNAT 14.2 or newer (Ada 2022 support required), gprbuild
- [Alire](https://alire.ada.dev) (any recent 2.x) — or plain gprbuild; the
  crate has zero dependencies outside the Ada runtime

## Building and testing

```bash
gprbuild -p -P ipfs.gpr          # library
gprbuild -p -P ipfs_tests.gpr    # tests + examples deps
./bin/ipfs_tests_runner          # offline suite, no network needed
```

The project compiles with `-gnatwa -gnatwe` (all warnings as errors) — your
contribution must build warning-free on both GNAT 14.2 and 16.1 (the CI
matrix).

## What a good change looks like

1. **Spec-first.** Multiformats behaviour is defined by upstream specs
   (varint, multihash, multibase, CID). Cite the spec rule in a comment when
   behaviour is subtle (e.g. why a 10-byte varint can be legal).
2. **A regression test for every fix.** If you found a bug, add the test that
   fails on the old code (verify by temporarily reverting your fix).
3. **Reject, don't coerce.** Decoders raise `Malformed_*` exceptions on
   invalid input; they never silently decode garbage to zero bytes.
4. **No new dependencies.** Pure Ada, no OS-specific bindings.
5. **Style**: 3-space indentation, GNAT warning-clean, `pragma Ada_2022` where
   aggregates are used.

## Commit / PR conventions

- Conventional commits (`fix:`, `feat:`, `docs:`, `test:`, `ci:` …).
- One logical change per PR; include repro/test output in the PR body.
- MIT license; by contributing you agree your work is licensed under the
  repository's MIT `LICENSE`.

## Releasing (maintainers)

1. Bump `version` in `alire.toml` and update `CHANGELOG.md`.
2. Tag `vX.Y.Z` — the release workflow enforces tag/manifest version parity,
   builds, runs the suite, and attaches a source archive + sha512.
3. Update the Alire community index (`stable-1.4.0` branch) with the new
   release toml, pinning the release **commit SHA** (not a tarball hash).
